# ADR-0004: 报错文案放在 `i18n/*.toml`

- **状态**: Accepted
- **日期**: 2026-11-14

## 背景

报错文案原本直接写在 C# 里(`throw new RuntimeException("…")`、`ParseError("…")`),
一共 206 条,散在 `Runtime/`(141)与 `Syntax/`(65)的 47 个文件里。这带来两个麻烦:

- 想换一门语言,得改 47 个文件、重新编译;
- 同一句话在两处写了两遍(`未定义的变量 '{0}'`、`{0} 没有方法 '{1}'` 这种),改一处漏一处。

试过 .NET 的标准做法(`Resources/Messages.resx` + `ResourceManager`),被两个理由否掉:
XML 里全是实体转义、人读不了;而且调用点写 `Messages.UndefinedVariable` 这类生成属性,
名字是本机半自动起的,和"这句话在说什么"没关系。

## 决策

> **一条文案一行 `键 = "文案"`,放在 `i18n/zh.toml`;代码里只剩 `Messages.T("键", 实参…)`。**

四条细节各自有理由:

1. **中性语言是中文**。中文原文就是唯一真源,不做"先英文再译中文"那一趟转手印刷。
2. **键是 `<域>.<子域>.<条目>`,不许数字序号**。`parse.lexer.unexpected_char` 自带含义,
   能在 `grep` 里被搜到;`errors.007` 什么都说明不了,还得回来查表。
   域按"谁在报错"分:`parse.lexer` / `parse.pattern` / `runtime.call` / `runtime.scope` …
3. **TOML 而不是 JSON / resx**。一条一行、占位符 `{0}` 看得见、注释能写;不用为了转义读成乱码。
4. **两处兜底**:`i18n/` 随发布拷到 `out/i18n/`,同时用 `EmbeddedResource` 嵌进程序集。
   所以"整个 `out/` 换了目录"照旧能跑,"只拷走 `ravel.dll` 一个文件"也能跑(内置中文)。

切换:`RAVEL_LANG=en` 或 `--lang en`;缺的键回退中文,不是回退键名 —— 半翻的词典也还能用。
**标准库(`lib/*.rav`)的文案不进来**:那是用户可改的源码,不是引擎的一部分。

## 代价

- 报错时多一次字典查找(可忽略),但**改了文案就得同时改 TOML 与调用点**这两处 ——
  由 `Messages.T` 的键做锚:键在表里找不到时,输出的是键名本身,测试会立刻红。
- 一条文案若被两处复用,两边就共享同一个键;要分开说得更细,得拆成两条(词典里不会自己长出新词)。
